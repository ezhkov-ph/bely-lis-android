# Текстовый ребрендинг: «Белый лис»

Основа не менялась: стабильный тег `FIREFOX-ANDROID_154_0_1_RELEASE`,
ревизия `9cd094dbc3eac5df87a24e7a871e52880cb8cd42`.
Названия Fenix/Fennec в путях исходников не обозначают переход на Preview.

## Что подготовлено

- Общие строки `app_name`, `app_name_firefox`, `firefox`, системная подпись приложения
  и подписи вариантов release/beta/nightly теперь используют «Белый лис».
  Подготовка этих вариантов не означает, что мы стали собирать beta или nightly.
- Собственные упоминания браузера в приветствии, меню, настройках, уведомлениях,
  подсказках, виджете, локальных опросах и диагностических экранах заменены.
- Проверено 334 закреплённых входных файла Fenix, Android Components и активного
  неофициального брендинга Gecko. Изменяются только явно выбранные ресурсные ключи.
- Русские формулировки с названием и подстановками исправлены отдельно:
  например, «О браузере „Белый лис“», «Открыть в браузере „Белый лис“».
- На главном экране и двух экранах разблокировки растровую/векторную надпись
  Firefox заменяет обычный текст из `app_name`. Соседние изображения логотипа
  остаются прежними. В заголовке «О приложении» вместо прежнего изображения
  бренда используется текстовое название с сохранением входа в секретное меню.
- Экран «О приложении» прямо сообщает о независимой сборке на основе Mozilla
  Firefox с дополнительными российскими CA и об отсутствии связи/одобрения Mozilla.
- Отображаемые названия Fennec в активном `mobile/android/branding/unofficial`
  заменены. Технические идентификаторы Gecko не менялись.

В остальных локалях заменяется само имя в выбранных строках. Полная редактура
грамматики всех языков не выполнялась. Новый текст об авторстве подготовлен
на русском и английском; в остальных локалях для него используется английский текст.

## Что намеренно сохранено

| Область | Причина |
| --- | --- |
| Mozilla Public License, copyright, авторство, `vendor-short-name` | Это сведения об исходном коде и исходном поставщике, а не наше название |
| Mozilla Account, Mozilla VPN, Firefox Relay, Firefox Suggest, MLPA-провайдер Firefox | Это отдельные сервисы/поставщики; новое имя не меняет их владельца |
| Инструкции открыть Firefox на компьютере, подключить другие устройства и Sync | Десктопной версии «Белого лиса» у проекта нет |
| Названия и текст ссылок на документы Firefox/Mozilla, маркетинговые согласия | Нельзя переименовать чужие документы или выдать кампании Mozilla за наши |
| Получатель телеметрии/отчётов/исследований — Mozilla | Ребрендинг не меняет фактические настройки передачи данных |
| Пункт «Что нового в Firefox» | Он по-прежнему ведёт на журнал изменений исходного Firefox; для него добавлен отдельный `upstream_firefox_name` |
| URL, package namespace, resource keys, идентификаторы API, User-Agent | Их массовое переименование может сломать совместимость |
| Картинки онбординга и удалённый контент Mozilla | Новый launcher-логотип подготовлен отдельно; остальные изображения требуют последующего аудита |

Публичная версия ещё требует аудита остальных изображений, внешних ссылок
(включая магазин/скачивание/поддержку), удалённым кампаниям, согласиям, подписи и обновлениям.
Наличие имени «Белый лис» не означает, что эти функции уже принадлежат нашему проекту.

## Где менять и как повторить

- `config/branding.json` — имя и текст об авторстве.
- `config/branding-ru.json` — конкретные русские формулировки.
- `scripts/branding.mjs` — список выбранных ключей, исключения и изменения экранов.
- `config/branding-source-hashes.json` — SHA-256 входных файлов точной версии Firefox.
- `scripts/prepare-overlay.mjs` — общая подготовка сертификатов и текстового ребрендинга.
- `artifacts/text-branding-report.json` — каждый изменённый текст и оставшиеся упоминания с причинами.
- `artifacts/overlay-manifest.json` — полный набор подготовленных файлов и их отпечатки.

После получения входных файлов:

```powershell
npm run prepare:overlay
npm test
python scripts/validate-branding.py
```

Локальная проверка в уже настроенном WSL:

```powershell
wsl -d Ubuntu --user root --exec bash '/mnt/c/Users/alex/Downloads/Firefox ru/scripts/build-session.sh' verify-branding
```

Она проверяет XML, применяет изменения к точной ревизии, запускает тесты безопасного
наложения и `mach gradle fenix:compileDebugKotlin`. APK не упаковывается и не подписывается.
Журнал: `work/linux-build/logs/branding-compile.log`.

Наложение допускает переход только с исходных файлов, уже идентичных новых файлов
или точно закреплённых предыдущих версий наших файлов из `config/branding.json`. Посторонние изменения
не перезаписываются. Повторная подготовка детерминирована.

## Ограничения проверки

Проверяется структура XML, сохранность ключей, атрибутов, комментариев и подстановок,
неизменность NSS, временной иконки и Gradle-настройки application ID.
Компиляция ресурсов/Kotlin не заменяет осмотр экранов на телефоне: длинные строки,
масштаб шрифта и переходы во внешние сервисы надо проверить в следующем APK.

Уже собранный `artifacts/apk/ru-browser-154.0.1-arm64-test.apk` не изменялся.
Его SHA-256 остаётся `e33e1e1f1bee1596186199df27850a2a50d37ecf0e138a7e9c012b4a67f34bde`.
Чтобы увидеть новое имя на устройстве, потребуется отдельная пересборка и установка.
После неё экспорт будет называться `bely-lis-154.0.1-arm64-test.apk`.
Скрипт экспорта теперь проверяет подпись имени приложения во всех локалях и
откажется выдавать старый APK под новым названием.
